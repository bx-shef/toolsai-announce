# Оповещения из ИИ-клиента (MCP)

> Последняя сверка: 2026-10-17 (1.6.0)

С 1.6.0 модуль отдаёт свои функции MCP-серверу линейки
([toolsai-mcp](https://github.com/bx-shef/toolsai-mcp), `docs/MODULE_TOOLS.md`):
сотрудник просит ИИ-клиент (Claude, чат ИИ-помощника shef.toolsaiassistant в
режиме «Агент») «сделай оповещение отделу продаж о…» — и объявление
появляется в списке модуля. Код сервера MCP и помощника не меняется: сервер
читает манифест модуля и показывает модели его инструменты.

## Инструменты

| инструмент | REST-метод | право на модуль | что делает |
|---|---|---|---|
| `announce_list` | `shef.announce.list` | R | все объявления: id, заголовок, вид, кому, включено ли, период, места, источник (`own` или id модуля) |
| `announce_create` | `shef.announce.create` | W | создать своё объявление |
| `announce_update` | `shef.announce.update` | W | изменить своё (`own`) по id, только переданные поля |
| `announce_disable` | `shef.announce.disable` | W | выключить; модульное — своей копией, как на странице списка |

Манифест — `shef.announce.mcp.tools`, область прав REST — `shef_announce`.
Сотруднику с правом R модель видит только список, без права — ничего.
Право проверяется и в каждом методе (манифест сервер кеширует 5 минут).

**Запуск — решает человек** (решение владельца: запуск на всех через MCP
разрешён, с подтверждением в клиенте). Аудитория у `announce_create` обязательна, и в
описании инструмента модели велено спросить человека и не выбирать самой:

1. черновик — `audience: test`, окно увидят только тестовые пользователи
   модуля; на всех включают потом (в списке или `announce_update`);
2. сразу сотрудникам — `audience: all` или `custom` (`users`, `departments`).

Запись в MCP — с подтверждением человека в клиенте (`kind: write`). Это и
есть защита от запуска на всех без человека: модуль запрещает только
запись без права W, «спросить человека» — текст для модели. Без `audience`
(вызов мимо схемы MCP) объявление создаётся черновиком на тестовых.

Встроенную картинку (`art`) выбрать можно; свою загрузить — только на
странице списка. Ссылки — только https, видео — из белого списка: REST
проверяет поля той же `Announcements::validate()`, что и форма.

Отказ (`INVALID_ARG_VALUE`, `LIMIT`, `ACCESS_DENIED`, `BUSY`) модель видит
кодом и текстом — что исправить («Выберите сотрудников или отделы»):
сервер MCP показывает текст отказа модуля с [toolsai-mcp#47](https://github.com/bx-shef/toolsai-mcp/pull/47);
на сервере старше — только код. Тексты ошибок модуля не содержат
персональных данных и ввода сотрудников.

Методы — обычный REST: их может вызвать и любое другое приложение или
вебхук с областью `shef_announce`, права при этом — сотрудника.

## Подключение

1. Модуль 1.6.0 стоит; подписка `rest:OnRestServiceBuildDescription` ставится
   установщиком или сама на первом хите после обновления копированием
   (`Main\Maintenance`). Проверка — `/rest/shef.announce.mcp.tools` под
   администратором.
2. Область `shef_announce` выдана приложению, через которое сотрудники входят
   в MCP; сотрудникам — войти заново. Без неё портал ответит
   `insufficient_scope` и инструментов не будет
   ([MODULE_TOOLS.md](https://github.com/bx-shef/toolsai-mcp/blob/main/docs/MODULE_TOOLS.md), чек-лист).
3. На `<адрес MCP>/admin` в «Модули портала» дописать `shef.announce.mcp.tools`.
4. Кому можно создавать — право «запись» на модуль и запись в MCP: её
   открывает администратор портала на `/admin` сервера (пусто — только
   администраторам портала) или `WRITE_USERS` сервера.

Не проверено на живой коробке — сверить на стенде: вид регистрации события
`rest` (старого вида, `isCompatible`, как у `calendar`); видна ли своя
область в правах локального приложения; появляются ли методы сразу после
обновления копированием (не кеширует ли rest описание); право модуля под
токеном сотрудника; чтение списка из `b_option` под блокировкой
(`OwnStore::fresh()`) — на MySQL портала.

Список своих объявлений пишется под блокировкой БД (`OwnStore::update()`), и
правка собирается внутри неё поверх списка из БД: одновременные вызовы
инструментов друг друга не затирают. Занято дольше 5 секунд — ошибка
`BUSY`, без записи. Выключение — без проверки формы, как кнопка на
странице списка: выключить можно и объявление с ошибкой в полях. Дату
публикации старых своих правка берёт из журнала первого появления.
